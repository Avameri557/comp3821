COMP3821 - Discussion notes: comparing N sizes and the social optimum
======================================================================


----------------------------------------------------------------------
1. Q: Why can't we just directly compare the 3 original graphs?
----------------------------------------------------------------------

You can, but you can't read much off them side by side. They differ in
three ways:

1. They plot total cost, not cost per agent. Total cost grows with the
   number of agents. At alpha = 0 in Pigou, every agent pays 1.6, so the
   totals are 32 for N = 20 and 128 for N = 80. That's the same outcome,
   but on the originals one curve sits four times higher than the other.
   Dividing by N puts them on one scale, so a gap between lines means a
   real difference.

2. Each graph sets its own y-axis. matplotlib fits every image to its own
   data. So with three separate images, the same height on the page means
   different values. Two curves can look equally deep when one dip is far
   larger.

3. They're separate images. Overlaid on one set of axes, you can see
   things a side-by-side comparison hides, such as N = 80 reaching its
   minimum at a smaller alpha than N = 20. That shift is the main thing
   the N comparison is meant to show.

The alpha x N graph does something different again. It changes the
x-axis to the number of agents each agent actually sees. The originals
can't show that the curves line up on that axis.

The originals are still useful for looking at one run on its own. The
combined graphs are for comparing across N.


----------------------------------------------------------------------
2. Q: Don't we need the total social cost to compare against the
      optimum?
   (Attached screenshot: a Pigou derivation with c1(f) = 1,
    c2(f) = f/N, SC(k) = k^2/N + N - k, optimum k = N/2, and
    SC = 22.5 with a 15/15 split for N = 30.)
----------------------------------------------------------------------

No. If you divide the optimum by N as well, the comparison doesn't
change. The gap between the simulation and the optimum is a ratio, and
dividing both by N cancels out:

    (simulated total / N) / (optimal total / N)
        = simulated total / optimal total

So a run that is 5% above the optimum is 5% above it in total cost and
5% above it in cost per agent. Per agent is the better choice when
comparing sizes, because the per-agent optimum is almost the same for
N = 20, 50 and 80. That gives you one reference line for all three
curves instead of three different ones.

Your derivation uses different weights from our runs. It uses
c2(f) = f/N, which is b x N = 1, the textbook weights. Our runs use
1.6 f/N. Redoing your calculation with our weights:

    Social cost:  SC(k) = 1.6 k^2 / N + N - k
    Derivative:   dSC/dk = 3.2 k / N - 1 = 0, so k = N / 3.2 ~ 0.31 N
                  rather than N/2
    Minimum:      SC* = N (1 - 1/6.4) = 0.844 N

    N    Optimal k   Optimal total cost   Per agent
    20   6           16.88                0.844
    50   16          42.19                0.844
    80   25          67.5                 0.844

k is rounded to whole agents, and the per-agent value is the same at
every size. N = 80 matches the optimum computed for the earlier report
(67.5).

With the N/2 split, we'd be comparing our results against the optimum of
a different network. That's also why the old break-even calibration
behaved so differently from the current one.

The combined graphs don't show the optimum yet. Options: add a dashed
per-agent optimum line to each cost graph (0.844 for Pigou, plus the
computed optima for Braess, Diamond and Grid), or plot each curve as a
ratio of simulated cost to optimal cost, where 1.0 means optimal; that
reads like a price-of-anarchy curve.

3. Q: How do you plan to calculate the per-agent optimum line? How will
      we compare this to static models (the social optimum in the
      literature)?
----------------------------------------------------------------------

HOW THE LINE WOULD BE CALCULATED

1. Find the best way to split the agents across routes. Given whole
   numbers of agents on each route, find the split with the lowest total
   cost, sum of f * c(f) over edges.
   - For Pigou and Braess, try every split.
   - For Diamond and Grid there are too many splits to try. Instead, add
     agents one at a time to the cheapest place, then keep moving single
     agents while that lowers the cost. This is guaranteed to find the
     true minimum here, because costs are linear in flow. On Pigou and
     Braess it matched trying every split exactly.
2. Divide by N. Do this separately for N = 20, 50 and 80.
3. Plot it as a dashed horizontal line. The values for the three sizes
   differ only in the 4th decimal place (from rounding to whole agents),
   so one line serves all three curves.

HOW THIS RELATES TO THE LITERATURE'S SOCIAL OPTIMUM

The static model in the literature (Wardrop, Beckmann, Roughgarden)
charges each edge for everyone who uses it during the trip. Our
simulator charges only for the agents on that edge in the same timestep.
So two routes only slow each other down if they reach a shared edge at
the same step.

The optimum computed both ways (per agent; identical for N = 20, 50 and
80 to 3 d.p.):

    Network   Static optimum (literature)   Optimum in our simulator   Same?
    Pigou     0.844                         0.844                      yes
    Braess    1.800                         1.644                      NO
    Diamond   2.739                         2.739                      yes
    Grid      5.131                         5.131                      yes

Why they match for three networks: in Pigou, Diamond and Grid, any given
edge is always reached at the same step, whichever route uses it. In the
grid, an edge out of the node in row r, column c is always step r + c.
So "everyone on the edge" and "everyone on the edge this step" are the
same people, and the two models agree exactly. For these three networks
our optimum IS the literature's static optimum, applied to whole agents
rather than a continuous flow. With this many agents, that rounding
makes no visible difference: Pigou's continuous value is 0.84375.

Why Braess differs: edge 3->4 is the second step of route 1->3->4 but
the third step of the zig-zag route 1->2->3->4. So in our simulator
those two groups of agents never slow each other down on 3->4. That
makes the shortcut genuinely useful, and the best achievable cost drops
from 1.8 to 1.644. This is the same Braess caveat as before.

WHAT TO PLOT

- Pigou, Diamond and Grid: one dashed line labelled "social optimum
  (static = simulator)".
- Braess: two lines, "static optimum (literature) 1.80" and "simulator
  optimum 1.64". The second is what the simulation could actually reach.
  The first is what a reader who knows the textbook result will expect.

That way, readers who compare against the literature have the number
they're looking for, and the gap between the two lines is explained
rather than hidden.

One more point: the optimum computation is currently a scratch script.
If the line goes on graphs in the repo, the script should go in too,
e.g. as src/benchmarks/social_optimum.py next to frank_wolfe.py. Then
anyone can reproduce the line.
